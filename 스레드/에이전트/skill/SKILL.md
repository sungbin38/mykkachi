## 요청 해석

- **“스레드 글 만들어줘” / “새 글” / “하나 더”**: 질문이나 유형 메뉴 없이 새 주제 1개를 골라 완성 원고를 바로 준다. 작성만 요청했으면 공개 게시하지 않는다.
- **주제·유형·분량 지정**: 사용자의 지정이 우선. 랜덤은 중복 방지 기준 안에서 다양하게 선택하라는 뜻이다.
- **“올려줘” / “게시해줘”**: 대화에서 특정한 원고를 API로 게시한다. “새로 만들어서 올려줘”는 작성부터 게시까지 수행할 권한이다. 게시 대상이 여러 개로 모호할 때만 대상을 묻는다. 이미 명확히 받은 게시 허가를 다시 묻지 않는다.
- **선택지 요청**: 이때만 활성 유형과 새로운 소재를 제시한다.
- **예시 추가**: `글유형.json`에 고유 ID로 추가하거나 기존형 참고를 보강한다. 기존 글과 ID를 유지한다.

## 매번 읽을 것

## 자동 주제 선택과 작성

사용자 최신 교정: **처음 제공한 본인 글의 형식을 유지하고 사주 소재·내용만 새로 쓴다.** 최근 AI가 작성한 정재·식신·역마 설명형 글은 스타일 참고로 쓰지 않고 중복 점검에만 사용한다. 기본은 사주 전용이며 MBTI는 따로 요청할 때만 쓴다. 상세 형식은 writing.md의 ‘원래 돈쌤 형식’을 우선한다.

1. 기본 후보는 운영설정의 `auto_format_ids`다. 최근 3편과 같은 핵심 개념·생활 장면을 피하고, 최근 20편 제목·topic_key와 의미가 겹치지 않는 소재를 고른다. 프로젝트 루트의 `스레드/03_게시글/00_목록.md`도 제목 중복 확인에 쓴다. 같은 문장에 십성·일주 이름만 바꾸지 않는다.
2. 일주·일간 번호 목록형과 십성·일간·신살의 짧은 하이픈 목록형을 섞는다. 기본은 **본문 1개 + 신청 댓글 1개, 총 2개**. 사용자 지정이나 분량상 필요한 경우에만 늘린다. MBTI는 명시적으로 요청했을 때만 작성한다.
3. **후킹 필수(사용자 지시 2026-10-11, 항상)**: 본문 첫 줄은 [hooks.md](references/hooks.md)의 10공식 중 하나로 쓴 후킹 한 줄이다. 직전 글과 다른 공식을 고르고, 초안에 `hook_formula`·`hook_line`을 기록한다. 통계·사례·후기를 꾸며내지 않는다.
4. 원본의 제목 틀, 항목 수와 줄바꿈, `~함/~임/~편` 말끝을 살린다. 명리 관계는 목록 안의 짧은 항목으로 녹인다. 정의·판정법·긴 주의 문단을 본문 뒤에 붙이지 않고 근거는 `notes`에 보관한다. 제목의 핵심 사주 개념과 상황·행동 내용은 새로 쓴다. 새로운 실제 상담 경험·후기를 꾸며내지 않는다.
5. 마지막 게시물은 주제와 연결하는 한 문장 뒤 **운영설정의 현재 CTA + 신청 링크 + 카카오 채널**. **현재 기본(2026-10-11 사용자 지시)은 10월 특가**: 10만원 리포트를 10월 31일까지 1만원, 익명 후기 활용 동의 시 5천원. 무료 리포트 이벤트는 종료됐으니 리포트를 무료라고 쓰지 않는다. 11월 1일 00:00 KST부터는 캠페인이 자동 만료되므로 `evergreen_cta_template`(cta_mode evergreen)을 쓴다. `campaign.cta_template`을 기본으로 쓰고 핵심 조건을 줄여 없애지 않는다. 사용자가 종료·조건 변경을 알리면 설정을 갱신한다. 확인되지 않은 3일·50명·마감 시각을 임의로 붙이지 않는다.
6. `스레드/초안/YYYY-MM-DD_<새-slug>.json`에 [publishing.md](references/publishing.md) 형식으로 저장하고 `threads.mjs validate`로 검증한다. 로컬 초안이 다음 요청의 소재 이력이다. 수정본은 같은 파일을 갱신한다.
7. 대화에는 후킹·제목과 복사할 수 있는 `1/N`~`N/N` 원고를 먼저 보여준다. 번호는 게시물 밖 구분이고 JSON `posts`에는 원문만 넣는다. 끝에 글자 수와 저장 링크를 짧게 적는다. 브라우저 임시저장은 별도 요청 시 실제 로그인 계정을 확인하고 처리한다.
