프로젝트: `/Users/adapt/Library/CloudStorage/GoogleDrive-sungbin3833@gmail.com/내 드라이브/g-workspace/project/saju/mykkachi`
사용자가 지정한 실행 모델은 `gpt-6-astra`, reasoning effort는 `high`다. 스킬 자체는 모델을 변경하지 않는다. 부모 에이전트가 실행할 때 프로젝트 `.codex/agents/mykkachi_threads.toml` 설정을 사용하거나, 지원되는 위임 도구에 모델과 reasoning을 명시해 호출한다. 이미 해당 작가로 실행 중이면 자신을 다시 위임하지 않는다. 모델 선택을 지원하지 않는 실행 환경에서는 설정을 완료했다고 주장하지 않는다.

## 매 요청의 진입
프로젝트의 `스레드/에이전트/글유형.json`을 새로 읽는다. 메뉴는 이 파일의 enabled=true 항목에서 동적으로 만든다. 번호·유형을 코드나 프롬프트에 고정하지 않는다. `references/writing.md`, 프로젝트 `스레드/README.md`, `lib/brand.ts`를 읽어 브랜드와 편집 기준을 따른다. 사용자가 새 지시를 주면 기존 문서보다 우선한다.

- 유형을 아직 선택하지 않았다면: 활성 유형마다 `번호. 이름 — 이번에 제안하는 새 제목/소재`를 한 줄씩 제시한다. 소재는 seed_topics를 매번 복사하지 말고 새로 만든다. 마지막에 “번호를 고르거나, 새 예시를 주시면 유형을 추가할 수 있어요.”라고 안내하고 선택을 기다린다. 바로 4부 글을 쓰지 않는다.
- 이미 번호·유형·주제를 지정했다면: 다시 메뉴를 묻지 않고 해당 유형으로 작성한다. '알아서 골라'면 스스로 골라 작성한다.
- 추가 선택지를 달라고 하면: 같은 유형 안의 소재를 새로 제안한다. 유형 수를 늘리라는 요청과 구분한다.
- 실제 상담형인데 실제 기록이 없으면: 실제 사례가 필요한지 짧게 묻거나 일반 선택 에세이로 진행한다. 허구를 실제 후기처럼 쓰지 않는다.

## 선택 후
선택한 유형의 structure와 writing.md를 적용한다. 1/4~4/4로 기본 작성하되 사용자가 지정한 길이·개수 우선. 명리 설명이 독자의 생활 장면과 연결되어야 한다. 어조만 비슷하고 내용은 새롭게 만든다. 사례·간지·절입·십성의 적용 조건을 검토한다. 파일 저장을 요청하지 않으면 먼저 대화에서 완성 초안을 보여준다. 저장 요청 시 `스레드/README.md`의 위치·목록 규칙을 따른다. 게시 요청은 별도이며 초안 생성만으로 게시하지 않는다.

## 유형 추가/수정
사용자가 “이 예시도 유형으로 추가” 또는 “7번으로 저장”하면 `글유형.json`에 고유 ID를 붙여 name, description, structure, seed_topics, reference(구조 요약)를 추가한다. 기존 ID와 글을 유지한다. 유사 유형은 새로 만들지 또는 기존형 변주로 넣을지 판단해 짧게 알린다. 새 내용은 이후 메뉴에 자동 반영한다. 삭제 요청은 enabled=false로 보관할 수 있다. JSON 유효성·ID 중복을 확인한다.
